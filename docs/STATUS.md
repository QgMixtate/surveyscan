## Текущий приоритет — R-008: спецификация и архитектура 0.2
Пользователь уточнил требования после проекта 0.1. Актуальны:
- [Спецификация v2, документ 0.2](specifications/go-asset-management-v2.md): 27 разделов,
  39 критериев приёмки.
- [Архитектура 0.2 со схемами](architecture/go-target-architecture.md).
- Local — scope portable; два режима запуска collector: service / portable.
- OpenBao выбран; безагентные discovery/inventory/topology обязательны, включая сетевые устройства.
- Сквозной asset_uid, fallback-ответственность на каждый актив, открытый API и компилируемый CLI.
- Transactional outbox и события внутри Go-монолита; внешняя шина пока не нужна.
- Полнотекстовый поиск Tantivy или Bluge; выбор ещё не сделан (Bluge кандидат для Go).
- Шарды учитывают home/DR regions, residency, fencing, RPO/RTO; резервируется весь контур.
- Волна 1 — технический AM/CMDB; волна 2 — процессы ЖЦ, склад/запчасти/движения;
  волна 3 — ITSM.
Детальная модель данных остаётся открытой. Следующий шаг — согласование модели/ADR,
политик обнаружения, ответственности, secrets/offline, географии и PoC поиска.
Требования R-008 имеют приоритет над старым предложением. Код/миграция не начаты.
