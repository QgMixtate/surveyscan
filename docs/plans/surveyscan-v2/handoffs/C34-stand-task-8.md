# Задание №8 для локального Claude (стенд awm.local, пилот C34): резервные копии и ответственные

Решения пользователя 2026-11-13: «настроить ежедневную копию на стенде», «ответственных назначает локальный Claude по
списку пользователя». Правила: sudo — только по подтверждению пользователя (временный sudoers удалить в конце);
секреты, пароли, ключи распечатывания и содержимое копий в чат и репозиторий не попадают; DC — только чтение.
Код на стенде не менять (стенд остаётся на 4c2dc99, 46 миграций).

## Часть 1. Ежедневная согласованная копия (pilot/ISSUES.md №4)
Опора: `v2/deploy/BACKUP.md`, `v2/scripts/checkpoint.py`, `v2/scripts/pg_backup.py`, `decisions/C39-disaster-recovery.md`.
1. Каталог копий `/var/backups/surveyscan` (root, 0700). Хранить 7 последних наборов. **Ограничение — сказать
   пользователю:** копии на той же ВМ защищают от ошибок и порчи данных, но не от потери ВМ; вынос на другой хост —
   отдельное решение.
2. Скрипт `/usr/local/sbin/surveyscan-stand-backup` (root 0700) — один согласованный набор:
   остановить центр (vm_center/systemd стенда) → `pg_dump` БД центра → снимок OpenBao Raft
   (`sys/storage/raft/snapshot`, токен — из уже существующего приватного файла стенда, не печатать) →
   `checkpoint.py build --writers-quiesced` (PG + Raft + каталог состояния центра) → запустить центр → проверить
   `/health/ready` → записать метку `{"completed_at":"<UTC RFC3339>"}` атомарно (временный файл + rename), 0600,
   владелец — пользователь процесса центра → удалить наборы старше 7 последних. Любая ошибка — центр всё равно
   запускается, метка **не** обновляется, код выхода ≠ 0 (видно в `journalctl`).
3. systemd: `surveyscan-stand-backup.service` (oneshot) + `.timer` ежедневно в 03:40 (локальное время ВМ),
   `Persistent=true`.
4. Центру задать `SURVEYSCAN_V2_BACKUP_MARKER=<путь метки>` (там же, где остальные переменные центра стенда),
   перезапустить центр.
5. Проверка: запустить сервис вручную один раз; затем
   - `pilot_report.py` (без `--origin`) → `backup_age_hours` — число < 1, предупреждения `BACKUP_AGE_UNKNOWN` нет;
   - `checkpoint.py verify --checkpoint <набор>` → OK;
   - пробное восстановление дампа PG в **отдельную временную БД** (не в рабочую!) и сравнение числа активов;
     временную БД удалить;
   - окно остановки центра при копии (секунды) — в отчёт.

## Часть 2. Ответственные (pilot/ISSUES.md №5)
1. Попросить у пользователя список «актив (имя хоста) → человек или команда (как в AD/разделе «Люди и команды»)».
   Не придумывать назначения.
2. Назначить через API центра (`POST /api/v1/assets/{asset_uid}/assignments` или массово
   `POST /api/v1/assignments/bulk`; роль — как в Web «Ответственность»), под учёткой admin, Origin — адрес центра.
3. Проверка: `pilot_report.py` → `with_owner_pct`; в Web у карточек видны ответственные.
