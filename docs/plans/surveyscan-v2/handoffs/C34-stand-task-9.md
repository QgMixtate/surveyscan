# Задание №9 для локального Claude (стенд awm.local): выкладка исправлений замечаний пилота №7–9

Правила: sudo — только по подтверждению пользователя (временный sudoers удалить в конце); секреты в чат не выводить;
DC — только чтение. **Новая миграция** (0047_directory_login, всего 48) — поэтому сначала свежая копия.

1. Показания «до»: миграций (46), активов/конфликтов, источников, `pilot_report.py` (без `--origin`).
2. **Свежая копия** перед выкладкой: `systemctl start surveyscan-stand-backup.service`, дождаться успеха,
   `checkpoint.py verify` последнего набора — OK. Без успешной копии выкладку не начинать.
3. Выложить `develop` (коммит не старше этого задания) — как в задании №7: `make build`, сервис поиска пересобрать
   (контейнер rust), центр перезапустить через vm_center `--persistent` **с `--backup-marker <путь метки>`** (один
   раз — дальше путь запоминается). Миграций должно стать 48 (применена ровно одна).
4. Проверки после:
   - №8: синхронизация AD прошла (полный прогон можно запустить кнопкой в Web), у людей из AD в «Люди и команды»
     заполнена колонка «Логин AD» (например, ar, sv);
   - №7: новых конфликтов на существующих 5 активах нет (их machine-id уже различны); сводка «клон → разбор»
     проверена в CI, на стенде клон специально не создавать;
   - №9: перезапустить центр вручную **без** `--backup-marker` → `pilot_report.py` всё равно без
     `BACKUP_AGE_UNKNOWN`;
   - №10: у win-ar в карточке появились ОС (название, сборка), процессор и список служб (состояние — «неизвестно»);
     в ошибках сбора остаются os/cpu/svcs — это ожидаемо (данные взяты из реестра);
   - доставка 8 источников без пропусков, конфликтов 0, `pilot_report.py` — без предупреждений.
5. Откат при сбое: восстановление из набора шага 2 по `deploy/BACKUP.md` / `decisions/C39-disaster-recovery.md`.

Отчёт одним сообщением (без секретов): коммит, миграций до/после, окно копии и выкладки, результаты проверок 4,
`pilot_report.py`, удалён ли временный sudoers, замечания.
