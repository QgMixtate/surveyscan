# Задание для локального Claude Code №3: выкладка C27–C30 на стенд и проверка (для приёмки E3)

Решение пользователя (2026-11-12): приёмка E3 — после проверки на стенде; SLO паспорта C30 утверждены (D-18).
Предыдущие задания: [C25](C25-stand-task.md), [C26](C26-stand-task.md). Правила — как в них (секреты не выводить и не
коммитить; sudo — только с паролем пользователя, `/etc/sudoers.d/90-claude-stand` удалить в конце; DC не трогать;
агентов не переподключать; с ВМ не пушить; при сбое — остановиться и показать хвост вывода). Журнал пишет облачная сессия.

## Шаг 1. Сборка
develop ≥ c68a7ee → git bundle → ВМ `/root/surveyscan` → `cd v2 && make build`.
Сервис поиска (Rust): на ВМ нужен тулчейн — если `cargo` нет, поставить rustup **для root** без пакетного менеджера
(`curl https://sh.rustup.rs -sSf | sh -s -- -y --profile minimal`; если сеть ВМ не пускает — сообщить пользователю,
не обходить). Затем `cd v2/search && cargo build --release --locked`.

## Шаг 2. Перезапуск центра с сервисом поиска
Записать «до» (активы, конфликты, миграции = 42). Ctrl-C в root-tmux `center`, затем:
`SURVEYSCAN_SEARCH_BIN=/root/surveyscan/v2/search/target/release/surveyscan-search .contract-tools/bin/python scripts/vm_center.py --persistent --public-host 10.170.108.2 --collector-port 18443`
Ожидается: `PERSISTENT стенд найден`, `READY`, миграций **43** (новая 0042_org). В журнале центра — строка
`search index rebuilt: 2 assets` (пустой индекс пересобирается автоматически). Через 5–10 минут — все 4 источника доставляют.

## Шаг 3. Ответственность (C27) — обратимо
1. «Оргструктура»: добавить человека «Проверка стенда» (логин — тот, под которым входишь в Web) и команду «Стенд»,
   включить человека в команду.
2. «Мои задачи» → «Не распределено»: оба актива там. Выбрать Linux-актив → «Назначить выбранным» ответственным
   человека. «На мне» — Linux-актив; вкладка «Ответственность» карточки — история (резервная команда → человек).
3. Отметить человека «Выбыл» → Linux-актив снова у резервной команды (основание «прежний ответственный выбыл»).
Скриншоты 2–3.

## Шаг 4. Поиск (C29)
Страница «Поиск»: `openssl` (Linux-актив, подсветка, фасеты), имя DC-хоста, IP Linux-ВМ; режим должен быть полнотекстовым
(нет красной плашки «Полнотекстовый поиск недоступен»). Затем остановить процесс поиска (`kill` PID из
`.local/vm-center-state/harness/search.pid`) → поиск показывает плашку запасного режима и находит точное имя; вернуть —
перезапустить центр командой шага 2 (индекс догонит изменения). Скриншоты.

## Шаг 5. Нагрузка (C30) на ВМ — только если пользователь подтвердит время (~25 мин, ВМ будет нагружена)
`cd v2/research/load && go build -o /root/loadgen . && cd ../..` затем
`SURVEYSCAN_LOAD_ASSETS=2000 LOADGEN=/root/loadgen SURVEYSCAN_SEARCH_BIN=$PWD/search/target/release/surveyscan-search .contract-tools/bin/python research/load/run.py /root/c30-stand`
(отдельная временная БД и центр на других портах; живой стенд не затрагивается, кроме нагрузки на ВМ).
В отчёт — сводка из `/root/c30-stand/report.json` (requests, throughput, p95/p99, errors, по действиям, resources).
