## Ключевые решения

- Asset UID отделён от agent/collector/source IDs. Mapping — tenant + origin source + namespace + local record.
  Перенос агента к другому collector не создаёт новый asset. Формулировка ID-03 спеки уточнена.
- Payload observations неизменяем. Temporal observation_links сохраняют историю назначения,
  а source_records содержит текущий mapping; их нельзя использовать для перепривязки всей истории молча.
- Current facts и диагностика последней попытки/последнего успеха раздельны. Partial/unavailable и late
  сохраняют пригодные значения. Manual business fields принадлежат Assets и не перезаписываются ingest.
- E1 автоматически повторно использует только проверенный mapping; cross-source ambiguity → conflict,
  raw claim asset_uid не авторизует доступ. Полное merge/split — C25.
- Minimum-one responsibility не обеспечивается одним UNIQUE: нужны owner guard/transaction/deferred check.
- TX-01/02/03 сознательно пересекают модули через owner ports внутри одного PG UnitOfWork.
  Это документированные препятствия будущему extraction, не обещание простого перехода на HTTP.
