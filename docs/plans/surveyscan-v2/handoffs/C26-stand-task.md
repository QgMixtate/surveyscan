# Задание для локального Claude Code №2: выкладка исправлений C25.03 и C26 на стенд

Решения пользователя (2026-11-11): выкладываем develop; два открытых конфликта закрыть «Подтвердить»; main перематывается
после успешной выкладки (это сделает облачная сессия по отчёту). Предыдущее задание и отчёт — [C25-stand-task](C25-stand-task.md),
REQUESTS R-027.

## Правила
Как в C25-stand-task: секреты не выводить и не коммитить; sudo — только с паролем от пользователя (файл
`/etc/sudoers.d/90-claude-stand` — по его решению и удалить в конце); DC не трогать; агентов не переподключать;
с ВМ не пушить; при сбое шага — остановиться и показать хвост вывода. Журнал REQUESTS.md дописывает облачная сессия —
локально журнал не правь, только отчёт пользователю.

## Шаг 1. Сборка
develop ≥ 83cfc4c → git bundle → ВМ `/root/surveyscan` → `cd v2 && make build` (как в шаге 1 прошлого задания).

## Шаг 2. Перезапуск центра
Записать «до» (активы, конфликты, наблюдения по источникам, миграции = 39). Ctrl-C в root-tmux `center`, та же команда
`vm_center.py --persistent ...`. Ожидается `PERSISTENT стенд найден`, `READY`, миграций **42** (новые 0039–0041).
Через 5–10 минут: все 4 источника доставляют, ошибок нет. Если показ Web (tmux `web` у ar) раздаёт старую сборку
из `web/dist` — перезапустить его на новой.

## Шаг 3. Закрыть два конфликта (решение пользователя)
Web → «Разбор конфликтов» → у каждого из двух конфликтов (записи SSH и Linux-агента, кандидат — Linux-актив 3d425d9d)
нажать **«Подтвердить»** (или API `POST /api/v1/reconciliation/conflicts/{id}/resolve` с `{"action":"confirm"}`).
Ожидается: в ответе `replayed_observations` в сумме 11; открытых конфликтов 0; непривязанных наблюдений 0.

## Шаг 4. Повтор слияния/разделения на исправленной сборке
Тот же обратимый сценарий, что шаг 3 прошлого задания (SSH-запись Linux-актива → новый актив → слияние обратно).
Ожидается теперь:
- клиент получает ответ (без обрыва TLS), записать время каждой операции и **через что** шли запросы
  (напрямую в центр или через nginx/показ Web);
- в окне между разделением и слиянием наблюдения SSH и агента продолжают применяться (новых конфликтов нет);
- после слияния: конфликтов 0, непривязанных наблюдений 0, карточка и разделы 1.2 как «до», старый UID → 308.

## Шаг 5. CMDB (C26)
1. Карточка Linux-актива: вкладки «ПО» (по имени, «Показать ещё»), «Компоненты», на «Обзоре» — класс и причина.
   Ручной класс не менять.
2. «Поиск ПО»: `openssl` — находит Linux-актив.
3. «Сервисы»: создать «Проверка стенда», связь «работает на активе» с UID Linux-актива; связь видна на вкладке «Связи»
   карточки; затем «Вывести из эксплуатации» — связь закрыта.
Скриншоты 1–3 — пользователю.
