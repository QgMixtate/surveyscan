# Задание №10 для локального Claude (стенд awm.local): C51.04 — обследование сети и сбор из Web

**Обновлено:** разделы 4–5 этого задания заменены заданием №11 (переход на `014526d`: новый экран, отпечаток ключа необязателен).

**Запускать только после того, как облачная сессия подтвердит зелёный hosted CI на коммите `49151e2`.**
Правила: sudo — только по подтверждению пользователя (временный sudoers удалить в конце); пароли и ключи вводит
**пользователь сам в Web** — в чат, файлы задания и журналы они не попадают; DC — только чтение; ничего не
сканировать вне подсети 10.170.108.0/24 (решение D-13 и разрешение пользователя 2026-11-13). Коммутатора на стенде
нет — SNMP в этом задании не проверяется.
Задание не зависит от того, выполнено ли №9: стенд может быть на 4c2dc99 (46 миграций) или a519ffe (48).

## 1. До выкладки
- Показания: коммит, миграций, активов/конфликтов, источников; `pilot_report.py` (без `--origin`).
- **Свежая копия:** `systemctl start surveyscan-stand-backup.service`, успех, `checkpoint.py verify` — OK.
  Без успешной копии не продолжать.

## 2. Выкладка `49151e2`
- `git fetch && git checkout 49151e2`, `make build`, сервис поиска пересобрать (как в задании №7), центр через
  vm_center `--persistent --backup-marker <путь метки>`. Миграций должно стать **51** (новые: 0047–0050 или 0049–0050).
- Новые агент и collector в `/opt/surveyscan` (как в задании №9), перезапуск служб collector и целей сбора (sudo).
  Collector стенда должен иметь право ICMP: если служба не root — `AmbientCapabilities=CAP_NET_RAW`
  (см. `deploy/systemd/surveyscan-collector.service`).
- **Пересобрать Web** (показ Web `~/ss-web` собирается отдельно от центра — без этого новые разделы не появятся): `cd v2/web && npm ci && npm run generate && npm run build`, затем обновить `~/ss-web` тем же способом, что при прошлых выкладках; проверить, что `version.json` показа Web указывает на выложенный коммит. В Web должен появиться раздел «Обследования сети» (пункт 10 меню).
- Проверки после выкладки: вход, реестр, доставка всех источников, AD, «Логин AD», копия видна (как в №9).

## 3. Обследование подсети из Web (C51.01–C51.02)
Пользователь (администратор) в Web → «Обследования сети» → «Новая подсеть»: `10.170.108.0/24`, сборщик стенда,
пробы TCP + ARP + ICMP, расписание «только вручную» → «Обследовать». Ждать «завершено» (до ~2 мин на /24).
- В отчёт: найдено / новых, адреса найденных узлов (без MAC — это не нужно), ошибки (если `icmp:not_permitted`
  — у collector нет CAP_NET_RAW), время обследования.
- Сверить с известными узлами стенда (.1 DC, .2 ВМ стенда, .5, .7, .10 и др.): кто найден, кто нет и почему
  (например, закрыты порты и не отвечает на пинг).
- Повторить обследование: «пропало» = 0 (если узлы не выключались).

## 4. Сбор найденных узлов из Web (C51.03)
1. Учётки (вводит пользователь в «Учётки сбора»):
   - SSH «Linux RO»: логин `scanprobe`, **закрытый ключ** — содержимое `/etc/surveyscan-targets/collect_ed25519`
     (пользователь сам копирует его в форму; Claude ключ не читает и не выводит);
   - WinRM «Windows RO»: логин `AWM\scanwinrm`, пароль — пользователь вводит сам.
2. Для win-ar: пользователь запускает на win-ar `v2/deploy/windows/prepare-winrm-target.ps1` (он идемпотентен,
   ответит `[ok]`) и берёт PEM-сертификат `C:\surveyscan-winrm-WIN-AR.pem`.
3. «Собирать» у найденных узлов: .5 и .7 — SSH, отпечаток ключа хоста — тот, что закреплён в задании №8 (сверить с
   хостом: `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`); .10 — WinRM, PEM и имя `win-ar.awm.local`.
4. Ждать в «Цели сбора»: «регистрируется…» → «собрано …» (до ~3 мин). При ошибке — текст из колонки «Состояние» и
   хвост журнала collector (`target_…` строки, без секретов).
5. Проверка в реестре: данные новых источников пришли в **те же** активы (simple2fa, calc-dep, win-ar), новых
   дублей и конфликтов нет; у win-ar есть ОС, процессор и службы (чтение из реестра при отказе WMI — №10 пилота).
6. Только после успеха и **с подтверждения пользователя**: остановить и отключить прежние файловые службы целей
   (`surveyscan-ssh-simple2fa`, `surveyscan-ssh-calc-dep`, `surveyscan-winrm-win-ar`); файлы учёток на ВМ пока не
   удалять (откат); отметить в отчёте, что их можно удалить после недели работы из Web.

## 5. Отчёт (одним сообщением, без секретов)
Коммит и миграций до/после; окно копии и выкладки; итог обследования (найдено/новых/ошибки/время, кто не найден и
почему); цели из Web — состояние и время первого сбора; дубли/конфликты (должно быть 0); win-ar — какие разделы
пришли; что отключено из файловых служб; `pilot_report.py`; удалён ли временный sudoers; замечания по Web.
