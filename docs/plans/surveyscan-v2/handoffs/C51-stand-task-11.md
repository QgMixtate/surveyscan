# Задание №11 для локального Claude (стенд awm.local): переход на `014526d` и сбор из Web на новом экране

Заменяет задание №10 после выкладки `49151e2`: обследование и сбор делаются **только на новом экране** (на старом экране
отпечаток ключа обязателен). Подсеть 10.170.108.0/24, если уже заведена в №10, сохраняется — повторно не заводить.

**Условие запуска:** облачная сессия подтвердила зелёный hosted CI на `014526d` (surveyscan-v2, surveyscan-boot,
surveyscan-web). Текст задания читать с `origin/develop` (`git show origin/develop:docs/plans/surveyscan-v2/handoffs/C51-stand-task-11.md`).

Правила (как всегда): sudo — только по подтверждению пользователя, временный sudoers удалить в конце; пароли и ключи
вводит **пользователь сам в Web** — в чат, файлы и журналы они не попадают; DC — только чтение; ничего не сканировать
вне 10.170.108.0/24; коммутатора нет — SNMP не проверяется.

Что нового в `014526d`:
- экран «Обследования сети» переделан: вкладки «Подсети / Учётки сбора / Цели сбора», формы в боковой панели;
- отпечаток ключа хоста SSH **необязателен**: если поле пустое, collector при первом подключении сам получает ключ
  хоста и закрепляет его в центре (в «Цели сбора» колонка «Ключ хоста» — «запомнен при первом подключении»);
  смена ключа потом — отказ «host_key_changed», сброс — кнопка «Сбросить ключ»;
- миграция 0051 (всего миграций станет **52**).

## 1. Перед выкладкой
- Показания: коммит, миграций (ожидается 51), активов/конфликтов, источников; итог обследования из №10, если уже есть
  (найдено/новых/время/ошибки) — в отчёт.
- **Свежая копия:** `systemctl start surveyscan-stand-backup.service`, успех, `checkpoint.py verify` — OK.
  Без успешной копии не продолжать.

## 2. Выкладка `014526d`
1. `git fetch && git checkout 014526d`, `cd v2 && make build`; сервис поиска пересобрать (как в задании №7).
2. Центр — через vm_center `--persistent --backup-marker <путь метки>` (как в №10). Миграций должно стать **52**.
3. Новые агент и collector в `/opt/surveyscan` (как в №9/№10), перезапуск службы collector (sudo). Проверить, что
   у collector осталось право ICMP (`AmbientCapabilities=CAP_NET_RAW`, если служба не root).
4. **Пересобрать Web:** `cd v2/web && npm ci && npm run generate && npm run build`, затем обновить `~/ss-web` тем же
   способом, что в №10. Проверить, что `version.json` показа Web указывает на `014526d`.
5. Пользователь обновляет страницу в браузере (Ctrl+F5) → «Обследования сети» должен показать **вкладки**
   «Подсети / Учётки сбора / Цели сбора». Если экран старый — Web не пересобран/не обновлён, дальше не идти.
6. Проверки после выкладки: вход, реестр, доставка всех источников, AD, «Логин AD», копия видна (как в №9).

## 3. Обследование подсети (на новом экране)
Если подсети ещё нет: вкладка «Подсети» → «+ Новая подсеть»: `10.170.108.0/24`, сборщик стенда, пробы TCP + ARP +
ICMP, расписание «только вручную».
Вкладка «Подсети» → у 10.170.108.0/24 «Обследовать» → ждать «завершено» (до ~2 мин). Повторить: «пропало» = 0.
В отчёт: найдено / новых / ошибки / время; кто из известных узлов (.1 DC, .2 ВМ, .5, .7, .10) не найден и почему.

## 4. Сбор найденных узлов из Web
1. Вкладка «Учётки сбора» → «+ Новая учётка» (вводит пользователь):
   - SSH «Linux RO»: логин `scanprobe`, способ «Закрытый ключ» — содержимое `/etc/surveyscan-targets/collect_ed25519`
     (пользователь сам копирует в форму; Claude ключ не читает и не выводит);
   - WinRM «Windows RO»: логин `AWM\scanwinrm`, пароль — пользователь сам.
   Если учётки уже заведены в №10 — повторно не заводить.
2. Для win-ar: пользователь запускает на win-ar `v2/deploy/windows/prepare-winrm-target.ps1` (идемпотентен, ответит
   `[ok]`) и берёт PEM `C:\surveyscan-winrm-WIN-AR.pem`.
3. Вкладка «Подсети» → узлы подсети → «Собирать…»:
   - .5 и .7 — SSH, учётка «Linux RO», **поле отпечатка оставить пустым**;
   - .10 — WinRM, учётка «Windows RO», PEM и имя `win-ar.awm.local`.
   Если цели уже созданы в №10 с отпечатком — не пересоздавать, оставить как есть (в колонке «Ключ хоста» будет
   «задан администратором»).
4. Вкладка «Цели сбора»: «регистрируется…» → «собрано …» (до ~3 мин). Для .5/.7 в «Ключ хоста» — «запомнен при
   первом подключении»; сверить отпечаток в колонке с хостом (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` на
   узле; без вывода ключей, только отпечаток). При ошибке — текст колонки «Состояние» и хвост журнала collector
   (строки `target_…`, без секретов).
5. Реестр: данные пришли в **те же** активы (simple2fa, calc-dep, win-ar), новых дублей и конфликтов нет; у win-ar
   есть ОС, процессор и службы.
6. Только после успеха и **с подтверждения пользователя**: остановить и отключить прежние файловые службы целей
   (`surveyscan-ssh-simple2fa`, `surveyscan-ssh-calc-dep`, `surveyscan-winrm-win-ar`); файлы учёток на ВМ не удалять
   (откат), отметить, что их можно удалить после недели работы из Web.

## 5. Отчёт (одним сообщением, без секретов)
Коммит и миграций до/после (51 → 52); окно копии и выкладки; виден ли новый экран (вкладки); итог обследования;
цели из Web — состояние, время первого сбора, происхождение ключа хоста (запомнен/задан) и совпадение отпечатка с
хостом; дубли/конфликты (должно быть 0); win-ar — какие разделы пришли; что отключено из файловых служб;
`pilot_report.py`; удалён ли временный sudoers; замечания по Web.
