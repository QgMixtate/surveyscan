# Задание №12 для локального Claude (стенд awm.local): схема сети и WinRM без PEM / «CA домена» / Kerberos

**Запускать только после того, как облачная сессия подтвердит зелёный hosted CI на коммите выкладки**
(указывается в сообщении облачной сессии; не раньше `0a7008f`). Текст задания читать с `origin/develop`.
Если задание №11 не выполнено до конца — сначала его разделы 1–2 (копия), остальное №11 заменяется этим заданием.

Правила (как всегда): sudo — только по подтверждению пользователя, временный sudoers удалить в конце; пароли и ключи
вводит **пользователь сам в Web**; **DC — только чтение**: групповые политики, AD CS и любые изменения на DC — только
с явного подтверждения пользователя (раздел 6 необязателен); ничего не сканировать вне 10.170.108.0/24.

Что нового (по сравнению с `014526d`):
- схема сети редактируется (C22.04): значки по типам, свои устройства, связи, зоны, подписи, авто-раскладка;
- WinRM-цель: PEM необязателен — сертификат запоминается при первом подключении («Сбросить сертификат» при смене);
- «CA домена»: корневой сертификат AD CS загружается один раз (вкладка «Учётки сбора»);
- **HTTP 5985 + Kerberos** по полному имени ПК и доменной учётке, сообщения шифруются, NTLM не используется;
- миграции 0052–0055: всего станет **56**.

## 1. Перед выкладкой
Показания (коммит, миграций, активов/конфликтов, источников); свежая копия `surveyscan-stand-backup.service` +
`checkpoint.py verify` — OK. Без успешной копии не продолжать.

## 2. Выкладка
`git fetch && git checkout <коммит>`, `cd v2 && make build`, сервис поиска, центр через vm_center
`--persistent --backup-marker …` (миграций **56**), новые агент и collector в `/opt/surveyscan`, перезапуск collector
(sudo), **пересборка Web** и обновление `~/ss-web` (`version.json` — выложенный коммит). Ctrl+F5 в браузере.

## 3. Схема сети (C22.04)
Пользователь: «Схема сети» → «Редактировать» → добавить коммутатор (если на стенде есть — с реальным именем),
провести связи к 2–3 узлам, создать зону «Стенд», «Разложить», «Сохранить схему». Обновить страницу — правки на
месте. В отчёт: типы, определённые автоматически (DC, ВМ стенда, win-ar, simple2fa, calc-dep: сервер/АРМ/ВМ/
гипервизор), что неверно — с причиной; удобно ли; снимок экрана (без секретов).

## 4. WinRM: HTTPS без PEM (сертификат запоминается)
1. Если цель win-ar по WinRM уже есть (№11) — оставить. Иначе: «Обследования сети» → узел .10 → «Собирать…» →
   WinRM, «Подключение: HTTPS 5986», «Проверка: запомнить при первом подключении», PEM не вставлять.
2. Ждать «собрано»; в колонке — «сертификат запомнен при первом подключении». Сверить отпечаток SHA-256 с win-ar
   (на win-ar: `(Get-ChildItem WSMan:\localhost\Listener | ? Keys -contains 'Transport=HTTPS')` → отпечаток
   сертификата → `Get-FileHash` его DER — или показать пользователю для сверки визуально).

## 5. WinRM: HTTP 5985 + Kerberos (по имени ПК)
Подготовка (только чтение, кроме win-ar с подтверждения пользователя):
- с ВМ стенда: `host -t SRV _kerberos._tcp.awm.local` — есть записи DC; `nc -vz <DC> 88` — открыт;
  `timedatectl` — время синхронизировано (расхождение с DC < 5 мин);
- на win-ar (пользователь, «от администратора»): `winrm enumerate winrm/config/listener` — есть HTTP 5985;
  если нет — `winrm quickconfig -q` (создаёт HTTP-прослушиватель) — **с подтверждения пользователя**;
  брандмауэр: 5985 только с адреса collector (`New-NetFirewallRule … -LocalPort 5985 -RemoteAddress 10.170.108.2`);
  `setspn -L win-ar` (на любом ПК домена, чтение) — есть `HTTP/win-ar.awm.local` или `HOST/win-ar.awm.local`
  (HOST покрывает HTTP).
Цель: «Собирать…» у .10 → WinRM, «Подключение: HTTP 5985 + Kerberos», «Полное имя ПК»: `win-ar.awm.local`, учётка
«Windows RO» (`AWM\scanwinrm`). Если цель WinRM на .10 уже есть по HTTPS — сначала отключить её (одна цель на адрес).
Ждать «собрано». При ошибке — текст из колонки «Состояние» и хвост журнала collector (строки `target_…`, без
секретов); для диагностики можно один раз запустить collector с `SURVEYSCAN_AGENT_DEBUG=1` (текст ошибки WinRM).
Проверка: данные пришли в **тот же** актив win-ar, дублей/конфликтов нет; на win-ar в журнале «Безопасность» вход
учётки сбора — **Kerberos** (событие 4624, «Пакет проверки подлинности: Kerberos»), не NTLM.

## 6. Необязательно, только с подтверждения пользователя: «CA домена» и GPO
- Если в домене есть AD CS: выгрузить корневой сертификат (`certutil -ca.cert C:\awm-root-ca.cer`,
  `certutil -encode … .pem`) — **открытый сертификат**, его можно передать; пользователь загружает его в Web
  («Учётки сбора» → «CA домена для WinRM»); цель «HTTPS 5986, проверка: CA домена» для ПК с сертификатом от AD CS.
- GPO по `deploy/OPERATIONS.md`, раздел 11 — на **тестовой OU** с одним ПК; создание GPO на DC — только
  пользователь сам или с его явного подтверждения. В отчёт: что получилось, что в руководстве неточно.
