ВМ — без обвязки vm_center, только по документам. Делать после задания №3 (C27–C30). Правила — как в заданиях №1–3:
секреты не выводить и не коммитить; sudo — только с паролем пользователя (временный `/etc/sudoers.d/90-claude-stand`
удалить в конце); DC и живой стенд (10.170.108.2) не трогать; с ВМ не пушить; при сбое — остановиться, хвост вывода.

## Предпосылка (от пользователя)

## Шаги (каждый — что сделано, команда, итог, время; где документ неясен или неверен — записать дословно)
1. **Выпуск:** на машине разработки (develop ≥ 3acac4d) собрать подписанный выпуск с сервисом поиска по RELEASE.md
   (ключ подписи — временный, сгенерированный локально, в отчёт не попадает); перенести бандл и открытый ключ на ВМ.
2. **Установка** по OPERATIONS.md §1: PostgreSQL 17, OpenBao 2.7.2, `release.py verify` + `stage`, systemd-службы,
   `bootstrap-admin`, вход в Web. Ожидается: миграций 45, `healthcheck` OK, diagnostics без предупреждений кроме
   BACKUP_AGE_UNKNOWN.
3. **Источник:** зарегистрировать Linux-агент на этой же ВМ, дождаться инвентаризации 1.2 в Web.
4. **Резервная копия** по §3 и BACKUP.md; затем **восстановление** на чистую БД той же ВМ; вход и запись работают,
   актив и его история на месте.
5. **Обновление** по §2: собрать выпуск следующей версии (тот же код, версия +1), `updater.py prepare/apply`;
   затем отозвать новую версию (`release.py revoke`) и убедиться, что `prepare` её отвергает, а `status` показывает
   `active_revoked`.
6. **Диск/сеть:** остановить центр на 10 минут → агент копит данные → запустить → данные досланы (§4).
