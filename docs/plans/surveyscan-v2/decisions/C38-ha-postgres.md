# C38 — HA PostgreSQL и георезервирование ячейки

Статус: решение пользователя 2026-11-13 — делать E5 по порядку; выполнено в песочнице (R-027). Значения RPO/RTO ниже —
предложение по умолчанию; подтверждаются пользователем для своей площадки (два ЦОД/региона на стенде пока нет).

## C38.01 — регионы, RPO/RTO, домены отказа
- **Пара на ячейку:** один писатель (home-регион) + одна потоковая физическая реплика (DR-регион). Каталог (C37) хранит
  для ячейки текущего писателя (`writer_node`) и **эпоху писателя** (`writer_epoch`, растёт при каждом переключении).
- **Асинхронная репликация по умолчанию.** Синхронная (`synchronous_commit=remote_apply`) добавляет к каждой записи RTT
  между регионами (≥ 10–40 мс между городами; запись карточки делает несколько запросов в одной транзакции) и
  останавливает запись при недоступной реплике. Асинхронная не задерживает запись, но **при внезапной потере писателя
  теряются транзакции, не дошедшие до реплики** (обычно доли секунды; измеряется — C38.04). Нулевая потеря не заявляется.
  Синхронная — опция для площадок с RTT < 5 мс (один город), включается настройкой PostgreSQL, код не меняется.
- **Цели (предложение):** плановое переключение — RPO 0 (ждём догон реплики), RTO ≤ 1 мин; потеря писателя/региона —
  RPO = отставание реплики в момент отказа (цель ≤ 5 с), RTO ≤ 15 мин с решением оператора (автоматического
  повышения нет: без третьего домена-арбитра автомат не отличает отказ региона от разрыва сети).
- **Домены отказа:** узел PostgreSQL, регион (узел + центр), разрыв между регионами. Центр (api/worker) в каждом регионе
  подключается строкой с двумя узлами и `target_session_attrs=read-write` — сам находит писателя.
- **Владение:** каталог и переключение — администратор платформы (команды `surveyscan-router`); резидентность данных
  (`catalog.tenants.residency`) ограничивает выбор DR-региона для организаций ячейки.

## C38.02 — переключение и ограждение (fencing)
`surveyscan-router failover -shard S -to N [-old-unreachable]`:
1. Каталог: ячейка `state=failover` — маршрутизатор отвечает 503 по организациям ячейки (новых запросов нет).
2. **Ограждение старого писателя:** `ALTER SYSTEM SET default_transaction_read_only=on` + перечитывание настроек +
   завершение клиентских соединений. Настройка хранится в файле узла и **переживает перезапуск**. Код центра не
   выполняет `SET` (архитектурный тест C36), поэтому снять запрет из приложения нельзя. Центры при переподключении
   отвергают узел только для чтения (`target_session_attrs=read-write`).
   Если старый узел недоступен — переключение только с флагом `-old-unreachable`: оператор подтверждает, что узел
   выключен или изолирован (STONITH: питание/сеть ВМ).
3. Старый доступен: ждём, пока реплика проиграет WAL до позиции старого писателя (RPO 0). Недоступен: фиксируем
   последнюю проигранную позицию и время последней транзакции — оценка потери.
4. Повышение реплики (`pg_promote`), сброс запрета записи на новом писателе.
5. Каталог: `writer_node=N`, `writer_epoch+1`, `state=active` — одной транзакцией, с записью в журнал каталога.
**Сторож писателей** (в `surveyscan-router serve`, раз в 10 с; и командой `check-writers`): узел ячейки, который
принимает запись, но не является писателем по каталогу (вернулся после разрыва), немедленно ограждается. Окно
двойной записи при нарушении STONITH — до интервала сторожа; оно названо остаточным риском.

## C38.03 — ранбуки и восстановление работ
- **Потеря писателя:** проверить, что узел/регион действительно потерян и изолирован → `failover -old-unreachable` →
  пересобрать индекс поиска (`POST /api/v1/search/rebuild`; индекс мог содержать потерянные транзакции) →
  сверить журнал синхронизации AD (повторный прогон идемпотентен).
- **Плановое переключение / возврат (failback):** старый узел пересоздаётся репликой нового (`pg_basebackup`, либо
  `pg_rewind`), после догона — `failover -to <старый>` без флага (RPO 0).
- **Работы после переключения:** аренды работ (`messaging.work_leases`) — в БД и реплицируются; аренда процесса,
  потерявшего БД, истекает по сроку, следующий держатель берёт её на новом писателе. Отметки потребителей событий —
  в той же транзакции, что и события: при асинхронной потере теряются вместе (повторов нет, пропусков нет).
  Уведомления (вебхуки) — «как минимум один раз»: отметка о доставке могла потеряться, повтор приходит с тем же
  `X-SurveyScan-Event-Id` (получатель отбрасывает дубль). Процессы центра, подключённые к огражденному узлу, не могут
  ничего записать: попытка — ошибка «только чтение», повторных эффектов нет.

## C38.04 — измерение (`scripts/ha_smoke.py`, в CI)
Два контейнера PostgreSQL (писатель + потоковая реплика), центр со строкой на два узла, маршрутизатор, поток
подтверждённых записей через API во время отказа. Сценарии: плановое переключение, потеря писателя (kill),
возврат старого узла после «разрыва» (сторож ограждает), возврат (failback) на пересозданный узел. Отчёт с метками
времени: RTO (от отказа до первой успешной записи), число подтверждённых и потерянных записей.

**Результат в песочнице (2026-11-13, один хост, сеть docker — RTT между «регионами» ≈ 0; на реальных регионах окно и потеря больше):**
| Сценарий | Недоступность записи | Подтверждённых записей / потеряно |
|---|---|---|
| Плановое переключение A→B | 0,15 с (1 неудачный запрос) | 113 / 0 (отставание реплики перед повышением — 0 байт) |
| Потеря писателя B (kill), переключение на A с `-old-unreachable` | 2,25 с, включая решение оператора (команда сразу) | 1 031 / 0 — в этом прогоне; асинхронная репликация без гарантии |
| Возврат B после «разрыва» (поднялся писателем) | 0 с | сторож оградил B через 10,0 с; запись в B — ошибка «только чтение» |
| Возврат (failback) A→B на пересозданную реплику | 0,1 с | 1 404 / 0 |
Не доказано и не заявляется: нулевая потеря при внезапной потере писателя, RTO на реальной межрегиональной сети, работа
при «расщеплении» с центрами в обоих регионах (окно сторожа ≤ 10 с).
