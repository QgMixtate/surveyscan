# C31.01 — первый набор интеграций: направления, версии, авторизация, владение данными

Статус: предложено (R-027, 2026-11-12). Решения пользователя: оргструктура — **Active Directory** (LDAPS, только
чтение); интеграция по активам — **экспорт/импорт CSV**. Плюс исходящие уведомления (webhook) — C31.03 по плану.

## Владение данными (нет двух конкурирующих мастеров)
| Данные | Мастер | SurveyScan | Внешняя система |
|---|---|---|---|
| Люди: ФИО, почта, учётная запись, включён/отключён | **AD** | только читает; синхронизированного человека нельзя переименовать или отключить вручную | не получает записей от SurveyScan |
| Команды из групп AD (по фильтру) и их состав | **AD** | только читает | — |
| Локальные люди/команды (резервная команда площадки и т. п.) | SurveyScan | ведёт вручную | — |
| Назначения ответственности | **SurveyScan** | ведёт | AD их не знает |
| Наблюдаемые факты | источники сбора | проекции | — |
| Ручные бизнес-поля (имя, назначение, критичность, теги, класс) | **SurveyScan** | ведёт; CSV-импорт — операция оператора в SurveyScan, а не второй мастер | Excel/1С получают экспорт |
Двусторонней синхронизации нет ни в одной паре.

## 1. Active Directory → оргструктура (C31.02)
- **Направление:** AD → SurveyScan, только чтение. Протокол LDAPS (ldap:// — только для стенда разработки по явному флагу).
- **Авторизация:** отдельная учётка AD только на чтение; пароль — в приватном файле центра (как токен поиска),
  не в БД, не в логах. Настройка — блок `ldap_sync` конфигурации центра (URL, base DN, фильтры пользователей и групп,
  bind DN, файл пароля, CA, интервал).
- **Идентичность:** `objectGUID` (не логин и не DN — они меняются) → `responsibility.subjects.external_id`,
  `origin='ldap'`. Учётная запись входа связывается по `sAMAccountName` с пользователем SurveyScan, если он есть.
- **Синхронизация:** инкрементальная — по `whenChanged` с запасом 5 минут от прошлого успешного прохода; полная —
  раз в сутки (только она обнаруживает удалённые из AD объекты). Отключённый в AD (`userAccountControl` бит 2)
  или удалённый человек деактивируется штатным путём C27: его активы переходят резервной команде площадки.
- **Происхождение:** у субъекта — источник, внешний ID, время последней синхронизации; каждый проход — запись в
  журнале синхронизации (счётчики, ошибки) и аудит.
- **Защита от ошибочного снимка:** полный проход, который вывел бы больше max(10, ¼ активных субъектов каталога),
  отклоняется целиком (ошибка фильтра или каталога), ничего не меняется. Резервная команда площадки из каталога
  не выбывает (замечание в журнале). Вложенные группы участниками не считаются.
- **Ручные правки:** имя, контакт, выбытие и состав команд субъектов каталога в SurveyScan запрещены (409);
  связь со входом можно поправить вручную.
- **Версия контракта:** `ldap-sync/1` — набор читаемых атрибутов: objectGUID, sAMAccountName, displayName, mail,
  userAccountControl, whenChanged, member (для групп).

## 2. CSV: экспорт и импорт активов (C31.02)
- **Экспорт:** `GET /api/v1/assets/export.csv` (assets:read) — первая строка `#surveyscan-assets-csv;v1`, затем
  заголовок; UTF-8 с BOM (Excel), разделитель `;`. Колонки: asset_uid, business_revision, display_name, purpose,
  criticality, tags (через запятую), asset_class, observed_hostname, observed_os, accountable_subject_id, accountable_name,
  last_inventory_at. Значения, начинающиеся с = + - @, выгружаются с префиксом «'» (защита от формул), импорт его снимает. Только активы тенанта, без слитых.
- **Импорт:** `POST /api/v1/assets/import.csv?dry_run=true|false` (assets:write) — меняет только ручные поля
  (display_name, purpose, criticality, tags, asset_class) по asset_uid с проверкой `revision` (оптимистичная
  конкурентность). Пустая ячейка — «не менять»; «-» в asset_class — снять класс. До 10 000 строк, 8 МиБ. Ответ — по строке: применено / без изменений / устарела ревизия /
  не найден / ошибка поля. `dry_run` ничего не меняет. Изменения — история актива (причина CSV_IMPORT), аудит, outbox.
- **Версия:** первая строка обязательна; неизвестная версия формата — отказ целиком.

## 3. Исходящие уведомления (webhook, C31.03)
- **Направление:** SurveyScan → внешняя система (ITSM, мониторинг), подписка на типы событий outbox.
- **Аутентичность:** подпись `X-SurveyScan-Signature: v1=<hex HMAC-SHA256(secret, timestamp + "." + body)>` и
  `X-SurveyScan-Timestamp`; ключ подписки = HMAC-SHA256(мастер-ключ, тенант + ID подписки). Мастер-ключ — отдельный
  приватный файл центра `webhook_secret_file` (≥ 32 байт; не ключ подписи наблюдений: тот может жить в OpenBao
  Transit без выгрузки). Секрет в БД не хранится и выдаётся администратору один раз при создании подписки;
  смена секрета — новая подписка.
- **Идемпотентность:** `X-SurveyScan-Event-Id` = event_id outbox; получатель отбрасывает повторы. Доставка — потребитель
  outbox на подписку: «как минимум один раз», повторы с нарастающей паузой, после 5 неудач — dead letter.
- **Повтор (replay):** уже доставленное событие повторно не отправляется. Повтор dead letter — только явным
  действием администратора (политика), с аудитом.
- **Ограничения адреса:** только https; http — только loopback в режиме разработки.

## Реализация (C31.02, R-027, 2026-11-12)
Миграция 0043 (`subjects.origin='ldap'`, `external_id`, `synced_at`; журнал `directory_sync_runs`), блок `ldap_sync`
конфигурации центра (по умолчанию — атрибуты AD; для совместимых каталогов — `guid_attribute`, `login_attribute`,
`changed_attribute`), API `GET /api/v1/directory-sync`, `POST /api/v1/directory-sync/run` (`full`|`auto`), CSV
`GET /api/v1/assets/export.csv`, `POST /api/v1/assets/import.csv?dry_run=`; контракт `c31-integrations`; Web — панель
синхронизации и отметка «AD» в «Оргструктуре», «Обмен с Excel / 1С» в реестре. C31.03: миграция 0044 (`messaging.webhook_subscriptions`, `webhook_deliveries`),
потребитель outbox `webhook-fanout` (строки доставки только для событий после создания подписки — история не
рассылается), отправитель: 20 доставок за проход, аренда 60 с, тайм-аут 10 с, перенаправления не выполняются, пауза
30 с·2ⁿ⁻¹ (до часа), после 5 неудач — dead; API `GET/POST /api/v1/webhooks`, `PATCH /api/v1/webhooks/{id}`,
`GET …/deliveries?state=`, `POST …/deliveries/{event_id}/retry` (только dead, аудит); Web — раздел «Уведомления».

## Проверки (C31.04)
Мок и реальное подключение разделены: OpenLDAP в контейнере (песочница, синтетический каталог) — интеграционные
тесты; **реальный AD** — на стенде (DC 10.170.108.1), только чтение, учётка только на чтение — **требуется от
пользователя** (prerequisite). Webhook — тестовый HTTPS-получатель; реальная ITSM — нет (не задана).
