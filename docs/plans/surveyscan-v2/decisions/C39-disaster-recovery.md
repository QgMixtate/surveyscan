Статус: решение пользователя 2026-11-13 — делать E5 по порядку; выполнено в песочнице (R-027). На стенде не проводилось.

## C39.01 — состав DR-набора (что, где, почему)
| Компонент | Где | Как копируется | Без него |
|---|---|---|---|
| БД ячейки (активы, наблюдения, журнал приёма/дедупликации, алиасы слияний, история, аудит, outbox и отметки потребителей, аренды работ, сессии) | PostgreSQL ячейки | `pg_dump` при остановленных писателях, либо физическая копия реплики C38 | восстановление невозможно |
| Каталог организаций (шарды, размещения, epoch, логины, журнал) | БД каталога (C37) | `pg_dump` | маршрутизатор отказывает всем (закрыто) |
| Конфигурация маршрутизатора и ключ подписи маршрутов | приватные файлы | копия файлов 0600 | старые cookie маршрута недействительны (повторный вход) |
| OpenBao: Transit (неэкспортируемые ключи CA/подписи квитанций), KV (секреты сервера и интеграций C31.05), политики, аудит | Raft | снимок Raft (`sys/storage/raft/snapshot`) | агенты/collector не продлеваются, квитанции не подписываются, AD/вебхуки без секретов |
| Ключи распечатывания OpenBao (custody) | **отдельно** от набора, у ответственных | вне набора | снимок Raft не открыть |
| Файлы центра (TLS сервера, machine.json, конфигурация) | диск центра | копия каталога состояния (`checkpoint.py`) | центр не стартует |
| Подписанные пакеты выпуска и список отзыва | каталог выпусков (C33) | копия каталога выпусков с `SHA256SUMS` | нельзя переустановить ту же версию |
| Очереди агентов/collector на диске | узлы-источники | не копируются (остаются у источников) | — источники повторно досылают, приём идемпотентен |
| Индекс поиска | сервис поиска | **не копируется** | пересобирается из PostgreSQL при старте |
Набор согласован, только если снят из **одной точки остановки писателей** (`checkpoint.py --writers-quiesced`); копии,
снятые в разное время, считаются несогласованными. Каждый набор — с манифестом SHA-256; набор проверяется до
восстановления.

## Порядок восстановления (граф зависимостей)
1. OpenBao из снимка Raft на новом узле → распечатать ключами custody → проверить политики и ключи.
2. PostgreSQL ячеек (в новые кластеры) → `surveyscan-server migrate` (ничего не применяет для той же версии).
3. БД каталога → конфигурация маршрутизатора + ключ маршрутов (адреса новых ячеек — в конфигурации).
4. Центры (api/worker) → маршрутизатор → проверка входа, чтения и записи.
5. Поиск — пересборка; синхронизация AD — повторный прогон (идемпотентен); collector/агенты подключаются, досылают
   очереди — повторы отбрасываются журналом приёма.
Компонентов вне этого графа нет: всё, что не в наборе (поиск, очереди источников), восстанавливается из набора или
досылается источниками.

## C39.02 — OpenBao и пакеты выпуска
`bao_restore_smoke.py` (C13 + C39.02): снимок Raft → новый пустой узел → распечатывание ключами custody → политики
сервера, значения KV, **секрет интеграции, записанный как из Web**, неэкспортируемые ключи Transit подписывают
проверяемые вызовы, запрещённый ключ по-прежнему недоступен, исходный узел не изменён. Пакеты выпуска проверяются
по `SHA256SUMS` и подписи (`release.py verify`, C33) из копии каталога выпусков.

## C39.03 — работы, дедупликация, поиск после DR
`TestC39ReplayAfterRestoreRespectsLedgerAliasesAndTombstones`: повтор уже принятых пакетов — дубль (без новых
наблюдений, активов и событий); пакет источника поглощённого при слиянии актива попадает в канонический актив;
поглощённый UID остаётся алиасом и не воскресает. Восстановление байт-в-байт доказано учениями C39.04, поэтому
повтор на восстановленной БД эквивалентен. Повтор пакета реального агента через восстановленные collector/PG —
`checkpoint_smoke.py` (C13). Индекс поиска пересобирается из PostgreSQL (C29).

## C39.04 — учения (`scripts/dr_drill.py`, в CI)
Исходная среда (ячейка в своём кластере PostgreSQL, каталог, маршрутизатор, 20 записей и сессия через API) →
набор при остановленных писателях с манифестом → **исходная среда уничтожена** → восстановление в новый кластер и
новую БД каталога. Результат песочницы 2026-11-13: время восстановления (от проверки набора до первого успешного
запроса с сессией, выданной до копии) — 3,5 с; все 60 таблиц ячейки и 4 таблицы каталога совпали по числу строк и
хешу; потеря — 0 (набор снят при остановленных писателях); запись и новый вход работают.
**Не измерено:** восстановление на объёме реального стенда и по сети между площадками; потеря при наборе с работающей
системы (ограничивается RPO реплики C38); учения на стенде пользователя.
