# C30.01 — нагрузочный паспорт «100 активных пользователей» (PERF-01…04, D-18)

Статус: **предложено** (R-027, 2026-11-12), зафиксировано до испытаний. Численные SLO — предложение для решения D-18;
до утверждения пользователем результаты сравниваются с ними, но заявлением о ёмкости не являются (PERF-01, PERF-04).

## Пользователи (операционное определение)
- **Зарегистрированные:** 100 учётных записей тенанта (80 операторов, 15 наблюдателей, 5 администраторов).
- **Одновременно активные:** 100 виртуальных пользователей; каждый держит свою сессию браузера (вход один раз
  в разогреве) и выполняет операции из смеси с паузой «на подумать» 2–6 с (равномерно). Это ≈ 25 запросов/с к API
  в среднем — нагрузка живых операторов, а не стресс-тест.

## Смесь операций (реальные API Web UI; доли — от числа действий)
| Действие | Доля | Запросы |
|---|---|---|
| Реестр: страница списка | 25 % | `GET /assets?limit=50` (+ курсор следующей страницы в половине случаев) |
| Карточка актива | 20 % | `GET /assets/{uid}/inventory`, `GET /assets/{uid}/cmdb` |
| Поиск | 15 % | `GET /search?q=…` (имена, ПО, словоформы, IP) |
| Вкладка ПО | 10 % | `GET /assets/{uid}/software?limit=100` |
| Раздел 1.2 | 5 % | `GET /assets/{uid}/inventory/facts/{section}` |
| «Мои задачи» | 5 % | `GET /worklist?scope=…` |
| Схема сети | 5 % | `GET /topology` |
| Правка бизнес-полей | 10 % | `GET` карточки + `PATCH /assets/{uid}` с If-Match (412 при гонке — ожидаемый исход, не ошибка) |
| Передача ответственного | 5 % | `GET /assets/{uid}/assignments` + `POST …/assignments` с expected_version (412 — ожидаемо) |

**Фоновая нагрузка:** импорт portable-пакета (50 хостов, профиль 1.2) каждые 60 с на протяжении замера; индексация поиска
и потребитель версий outbox работают как в продукте.

## Данные
2 000 активов из portable-пакетов с полной инвентаризацией 1.2 реального Linux-хоста (≈ 700 пакетов ПО, службы, сеть),
по 2 наблюдения на актив (история), 100 субъектов ответственности, 50 сервисов CMDB со связями; поисковый индекс построен.

## Прогон
Разогрев 60 с (вход, прогрев кэшей) → замер 300 с → остановка. Один начальный прогон (C30.03 initial), затем
адресные повторы после исправлений. Клиент и сервер на одной машине (RTT ≈ 0) — **оговорка**: сетевые задержки не учтены.

## Железо
Облачная песочница: 4 vCPU, 15 ГиБ, PostgreSQL 16 в контейнере, центр (combined: API + worker), сервис поиска.
Не стенд и не прод. Повтор на стенде — отдельный шаг.

## Предлагаемые SLO (D-18, требуют утверждения)
| Показатель | Цель |
|---|---|
| p95 чтения (список, карточка, вкладки) | ≤ 300 мс |
| p95 поиска | ≤ 500 мс |
| p95 схемы сети | ≤ 2 с |
| p95 правок | ≤ 500 мс |
| p99 всех запросов | ≤ 2 с |
| Ошибки (5xx, обрывы, неожиданные 4xx) | < 0,1 % |
| Отставание очереди outbox / индекса поиска в конце замера | ≤ 60 с работы |

## Что фиксируется (PERF-02)
p50/p95/p99 и ошибки по каждому действию, пропускная способность, CPU/RSS центра и сервиса поиска, насыщение пула
соединений PostgreSQL, медленные запросы (pg_stat_statements, если доступно), возраст очереди outbox и отставание поиска.
