# D-13 — политика обследования сетей (discovery/presence) и раздел Web «Обследования сети»

Статус: **решение пользователя 2026-11-13** (по требованию пилота C34, замечание №6 и отчёт локального Claude).
До этого D-13 было «proposed, отложено» (C01-decisions); C19–C22 реализованы как библиотеки без встраивания в
collector/центр/Web.

## Решения
| Вопрос | Решение |
|---|---|
| Виды проб | **TCP + ARP + ICMP.** TCP — попытка соединения на порты 22, 135, 445, 3389, 5985, 5986, 80, 443, 161 (UDP 161 — SNMP только при заданном профиле SNMPv3); ARP — только в подсети сборщика; ICMP echo — **сборщику нужно право CAP_NET_RAW** (выдаётся только службе collector, не root) |
| Кто заводит | **Администратор:** подсети (CIDR), привязка к площадке и сборщику, профили проб, учётки сбора (SSH/WinRM/SNMPv3) в OpenBao — ввод только в Web, значения не показываются и не попадают в журналы |
| Кто запускает | **Оператор:** ручной запуск и расписание обследования заведённых подсетей; ничего вне заведённых подсетей не сканируется (строгий scope C20) |
| Ограничения | подсеть не шире **/22** (1 024 адреса); не более **50 проб/с** на сборщик; расписание не чаще **раза в час**; одновременно одно обследование на подсеть; тайм-аут пробы 1 с |
| Результаты | найдено / новое / пропало / вернулось (presence C21, пороги — по умолчанию C21.01); из найденного — «собирать по SSH/WinRM» (учётка из OpenBao, цель создаётся без правки файлов) и SNMP для сетевых устройств (C19) |
| Аудит | заведение/изменение подсетей и учёток, каждый запуск (кто, когда, сколько адресов) — в журнале аудита |

## Остаточные риски
ICMP и TCP-пробы видны средствам защиты сети — подсети заводятся только с разрешения владельца сети; CAP_NET_RAW
расширяет права службы collector (только сырые сокеты ICMP).

## Учётки сбора из найденного (решение пользователя 2026-11-13: «через центр»)
- Учётки (SSH: логин + пароль или ключ; WinRM: логин + пароль, сертификат/имя сервера; SNMPv3: пользователь,
  протоколы и ключи) вводит **администратор в Web** (раздел «Обследования сети» → «Учётки сбора»). Значения уходят
  в OpenBao (KV интеграций C31.05), обратно в Web/API/журналы не возвращаются — только название, тип и дата смены.
- Collector получает учётку **у центра по mTLS** непосредственно перед сбором и только для цели, назначенной ему;
  держит в памяти, на диск не пишет. Каждая выдача — в аудит.
- Цель сбора создаётся кнопкой у найденного узла: тип (SSH/WinRM/SNMP), учётка, для SSH — подтверждение отпечатка
  ключа хоста (без TOFU), для WinRM — сертификат. Файлы на ВМ не нужны.
