## C37.01 — ключ разбиения и модель каталога
- **Ключ — tenant_id.** Все данные организации живут в одном шарде («домашнем»). Межорганизационных JOIN/FK нет
  (проверено: каждая таблица модулей содержит tenant_id; исключения — служебные `platform.schema_migrations`,
  `messaging.work_leases`, корзины ограничения входа и `access.bootstrap_state` (запись о первичной настройке ячейки), они
  локальны для шарда и не переносятся).
- **Ячейка (cell) = шард:** обычный центр SurveyScan (api/worker/combined, C35) со своей PostgreSQL. Код центра не
  знает о шардах; маршрутизация — отдельный процесс `surveyscan-router` перед ячейками.
- **Каталог** (отдельная БД, один писатель — маршрутизатор/администратор):
  | Таблица | Поля |
  |---|---|
  | `catalog.shards` | shard_id, регион, состояние (active / draining) |
  | `catalog.tenants` | tenant_id, shard_id, **epoch** (растёт при каждом переносе/переключении), state (active / migrating), home_region, dr_region, residency |
  | `catalog.logins` | username → tenant_id (логин уникален глобально; конфликт между шардами — вход закрыт до разбора) |
  | `catalog.events` | журнал изменений каталога (кто, что, epoch) |
  Адреса ячеек и пароли БД — в приватной конфигурации маршрутизатора, не в каталоге.
- **Крупная организация** не делится между шардами: верхняя граница организации — ёмкость одной ячейки (C30:
  2 000 активов / 100 пользователей с запасом; рост — вертикально и раздельными ролями C35). Межплощадочные связи
  внутри организации остаются в её шарде.
- **Межшардовые транзакции не поддерживаются.** Глобальные значения: UID активов — UUIDv4 (коллизии не проверяются
  каталогом), логины — через `catalog.logins`.

## C37.02 — маршрутизация (failure-closed)
- Вход `POST /api/v1/auth/sessions`: логин → организация → шард (только при state=active) → запрос в ячейку; при
  успехе маршрутизатор ставит cookie маршрута `ss_route` = tenant.epoch, подписанный HMAC ключом маршрутизатора.
- Остальные запросы: подпись cookie → организация → текущий шард из каталога (кэш ≤ 2 с) → ячейка.
- **Отказ закрыто:** нет каталога, нет/поддельная cookie, организация не найдена, state=migrating, логин в
  конфликте → 503/401; маршрута «по умолчанию» нет. Устаревшая epoch в cookie допустима (сессии переезжают вместе с
  организацией); шард всегда берётся из каталога, не из cookie.
- Транспорт агентов/collector (mTLS) идёт напрямую в ячейку организации (адрес в их конфигурации); при переносе
  меняется DNS-имя ячейки организации, агенты в окне переноса копят данные в очереди на диске (C10/C15).
- Фоновые работы (очередь событий, поиск, уведомления, AD) — внутри ячейки.

## C37.03 — перенос организации
`surveyscan-router move-tenant --tenant T --to B`:
1. **Проверка:** версии схем совпадают; в шарде B нет данных T; T в каталоге active.
2. **Пробная копия** (без заморозки): копирование и сверка, затем удаление пробной копии — оценка времени окна.
3. **Заморозка (fence):** каталог state=migrating (маршрутизатор перестаёт пропускать запросы организации), в шарде A
   `access.tenants.status=disabled` (вход, API и регистрация источников отказывают; агенты копят очередь).
4. **Копия** всех строк T из A в B одной транзакцией в B (триггеры неизменяемости отключены только для этой
   транзакции копирования: `SET LOCAL session_replication_role=replica`).
5. **Сверка:** по каждой таблице — число строк и хеш упорядоченного содержимого A = B.
6. **Переключение:** в B статус организации — прежний; каталог shard=B, epoch+1, state=active (одной транзакцией).
7. **Откат** при любом сбое до шага 6: удалить копию в B, вернуть статус в A, каталог state=active, shard=A.
После переноса данные T в A остаются отключёнными (не удаляются автоматически — для отката после переключения и
расследования); удаление — отдельная команда по решению администратора.
**Ограничение:** догоняющей репликации (CDC) нет — «догон» выполняется полным копированием под заморозкой; окно
переноса = время копии (оценивается пробной копией). Индекс поиска организации в B строится пересборкой.

## C37.04 — проверка
Две организации на двух шардах: изоляция (организация A недоступна через cookie B), подделка cookie, отказ каталога,
частичный отказ шарда при сводке по шардам, перенос с сохранением UID, сессий, истории и неизменяемых записей.
Сводка по шардам (`surveyscan-router summary`): параллельно не более 4 ячеек, тайм-аут 10 с на ячейку; недоступная ячейка
помечена, сводка — `complete=false` (неполные числа не выдаются за полные); проверяются дубли UID активов между
активными организациями разных шардов и организации, активные не в своём шарде по каталогу.
