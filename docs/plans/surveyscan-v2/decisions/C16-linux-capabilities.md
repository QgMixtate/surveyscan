# C16.01: матрица Linux capabilities, дистрибутивов и прав

Статус: **проектный документ (предложение)**. Ничего ниже не проверено на живых дистрибутивах, кроме явно отмеченного.
Основание: спецификация 0.5 §6.1, D-06 (proposed: Debian 13 amd64 для server/dev; agent OS — предложение до C08).

## 1. Что реально собирает Linux-агент сейчас (код `v2/internal/agent/inventory.go`)
| Секция | Источник | Состояние |
|---|---|---|
| identity | `os.Hostname`, `/etc/machine-id` (признак, не asset_uid) | реализовано, тесты Go |
| os | `/etc/os-release` → `/usr/lib/os-release`; архитектура из `runtime.GOARCH` | реализовано |
| network | `net.Interfaces` (без loopback, ≤512 интерфейсов, ≤64 адреса) | реализовано; DNS/маршруты/порты нет |
Остальное из §6.1 (оборудование, ПО/пакеты, обновления, службы, пользователи/группы, маршруты/порты, ФС/mounts/USB, защита, соседи) **не реализовано** — это C16.02.

## 2. Целевая матрица секций → источник → права (для C16.02)
| Раздел §6.1 | Источник (без внешних команд, где возможно) | Права | При отсутствии |
|---|---|---|---|
| Оборудование CPU/RAM | `/proc/cpuinfo`, `/proc/meminfo` | обычные | partial/unavailable |
| BIOS/serial | `/sys/class/dmi/id/*` (product_serial, product_uuid — часто только root) | root для serial/uuid | поле отсутствует, не синтезируется |
| Диски/ФС/mounts | `/proc/self/mountinfo`, `/sys/block`, statfs | обычные | partial |
| ПО/пакеты | dpkg (`/var/lib/dpkg/status`), rpm (`rpm` БД/`rpm -qa`), apk (`/lib/apk/db/installed`) — чтение файлов БД, без запуска менеджера | обычные (чтение) | unavailable с причиной «менеджер не поддержан» |
| Обновления | сведения пакетного менеджера, отдельно от Windows KB; доступность — без сетевого запроса | обычные | unavailable |
| Службы | systemd: `systemctl`/D-Bus (состояние+enablement); не-systemd — `unsupported` | обычные для чтения состояния | init не определён → секция unavailable |
| Пользователи/группы | `/etc/passwd`, `/etc/group` (без `/etc/shadow`, хэшей) | обычные | — |
| Сеть DNS | `/etc/resolv.conf`, systemd-resolved статус | обычные | partial |
| Маршруты/порты | `/proc/net/route`, `/proc/net/{tcp,tcp6,udp,udp6}`, `/proc/net/fib_trie`; владелец сокета (PID) требует root | обычные / root для PID | без PID — помечено |
| Защита | firewall (nft/iptables состояние — root), SELinux/AppArmor из `/sys/fs`, sshd_config (фильтр секретов) | root для firewall | partial |
| Соседи | ARP/NDP из `/proc/net/arp`, LLDP — расширение | обычные | partial |
Правила: пароли/хэши/ключи/содержимое пользовательских файлов не собираются; командные строки служб и конфиги фильтруются от секретов; TCP/UDP и секции независимы (сбой одной не ломает другие).

## 3. Дистрибутивы / init / пакетный менеджер (предложение поддержки)
| Сочетание | init | pkg | Статус предложения |
|---|---|---|---|
| Debian 13 (amd64) | systemd | dpkg | **целевое** (D-06), не проверено агентом |
| Debian 12, Ubuntu 22.04/24.04 (amd64) | systemd | dpkg | кандидат, не проверено |
| RHEL/Rocky/Alma 9 (amd64) | systemd | rpm | кандидат, не проверено |
| Alpine 3.x | OpenRC | apk | кандидат (контейнеры); службы — unsupported до решения |
| arm64 любого из выше | как выше | как выше | кандидат, сборка есть/нет — уточнить в C16.03 |
| Не-systemd (SysV/runit), кроме Alpine | — | — | **unsupported**: секция служб unavailable с причиной |
| Российские дистрибутивы (Astra, РЕД ОС, Альт) | systemd | dpkg/rpm | вне объёма до решения заказчика (CI/пилот нет) |
| Windows/macOS | — | — | не относится к C16 |

## 4. Профили прав
- **ограниченные** (непривилегированный пользователь службы): CPU/RAM, mounts, пакеты, passwd/group, сеть, /proc/net без PID — часть DMI и firewall недоступны → partial с причиной.
- **root** (служба от root или caps): + DMI serial/uuid, PID сокетов, firewall. Желаемый минимум caps вместо полного root — вопрос C16.03.
Каждый профиль требует отдельного стенда при приёмке (C16.04 / C24).

## 5. Открытые вопросы (не решены)
1. Окончательный список дистрибутивов (D-06 остаётся proposed).
2. Запуск менеджеров пакетов vs чтение БД файлов (предложено читать файлы).
3. Минимальные capabilities вместо root; поведение в контейнере.
4. Поддержка arm64 и не-systemd.

## 6. Что проверено
Только содержимое `inventory.go` по чтению кода. Живых прогонов на дистрибутивах, тестов правах и CI по этим сочетаниям нет.
