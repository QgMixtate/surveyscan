# C28.01 — PoC полнотекстового поиска: корпус, запросы, критерии и веса

Статус: зафиксировано **до** измерений (R-027, 2026-11-11). Результаты — C28-search-results.md, выбор — C28-search-adr.md.
Кандидаты (решение R-008): **Tantivy** (Rust) и **Bluge** (Go). PostgreSQL остаётся источником истины; индекс —
производная проекция, которую можно пересобрать.

## Корпус (детерминированный генератор `v2/research/search-poc/corpus.py`, seed фиксирован)
Документ = актив: `id`, `tenant` (5 тенантов, неравные доли), `site`, `os` (linux/windows/network), имя хоста
(латиница `srv-db-0123`, кириллица `бухгалтерия-пк-12`), FQDN, 1–3 IP, MAC, серийный номер (смешанный регистр),
владелец (ФИО по-русски), назначение (русский текст с разными словоформами), 5–40 установленных продуктов ПО
(англ. и рус. названия: `openssl 3.0.13`, `1С:Предприятие 8.3`, `КриптоПро CSP`).
Объём для измерений: **100 000** документов (+ проверочный 10 000). Плюс 1 000 обновлений и 2 000 удалений (tombstones).

## Запросы (ожидаемый результат вычисляет генератор по своим данным, не по движкам)
| Класс | Пример | Ожидание |
|---|---|---|
| точный хост | `srv-db-0123` | нужный актив — первый |
| префикс хоста | `srv-db-01*` | все такие активы тенанта |
| IP точный / подсеть | `10.20.3.17`, `10.20.3.` | точное совпадение / все в подсети |
| часть FQDN | `db-0123.corp` | нужный актив в первой десятке |
| серийный номер без учёта регистра | `ab12cd34` | нужный актив — первый |
| русская морфология | `бухгалтерии` ↔ «бухгалтерия» | все активы с этой основой |
| ПО англ./рус. | `openssl`, `1С Предприятие` | все активы с продуктом |
| сочетание с фильтром | `openssl` + `os=linux` | пересечение |
| опечатка (бонус) | `opensl` | актив с openssl в первой десятке |
Каждый запрос выполняется **в рамках тенанта**.

## Проверки-«ворота» (не прошёл — кандидат отклоняется независимо от баллов)
1. Изоляция тенанта: ни один ответ не содержит документ другого тенанта.
2. Удалённые документы не находятся после фиксации удаления.
3. Отзыв доступа не зависит от устаревшего индекса: результаты индекса — кандидаты, право проверяется по
   источнику истины (в PoC — авторитетная карта доступа); тест меняет доступ без переиндексации и требует ноль утечек.
   Контроль: без проверки по источнику утечка воспроизводится (тест не пустой).

## Критерии и веса (сумма 100)
| Критерий | Вес | Как измеряется |
|---|---|---|
| Корректность ответов на набор запросов | 30 | доля запросов, где ожидание выполнено (recall для наборов, позиция для точных) |
| Русская морфология и идентификаторы (IP/FQDN/serial) | 15 | подмножество запросов этих классов |
| Задержка запроса p95 на 100 000 | 15 | 50 повторов каждого запроса, один поток, тёплый кэш |
| Индексация и полная пересборка | 10 | время построения 100 000 и время пересборки |
| Ресурсы | 10 | размер индекса на диске, пиковая RSS процесса |
| Эксплуатационная пригодность | 20 | сборка и поставка (чистый Go / CGO / отдельный Rust-процесс), кросс-сборка Linux/Windows, размер бинарника, лицензия, сопровождение (свежесть релизов) |
Числовые критерии нормируются: лучший кандидат — полный вес, другой — пропорционально (для «меньше — лучше» — обратно).
Эксплуатационная пригодность оценивается по таблице фактов (версии, лицензии, даты релизов, команды сборки).

## Окружение измерений
Облачная песочница: 4 vCPU, 15 ГиБ ОЗУ, локальный диск; одна машина для обоих кандидатов, один прогон за другим.
Это **не SLA** и не обещание производительности на стенде/проде — сравнение двух кандидатов в одинаковых условиях.
