# C01: границы первого SMB-релиза E1

Дата: 2026-11-03, Москва. Архитектура 0.5. Пакет C01, результат C01.02.
Статус: рабочая граница исполнения плана; архитектура целиком не объявляется утверждённым ТЗ.
Источник: R-011, R-012 и разрешение R-013 выполнять поэтапно; последнее уточнение — выполнять исходный план с самого начала, без перестановок.

## 1. Что получает пользователь

Постоянно работающий сервер с отдельным Web UI, постоянным реестром PostgreSQL и
минимальными API/CLI. Зарегистрированный агент периодически собирает сведения только
своего хоста и передаёт назначенному площадочному collector. Collector хранит и доставляет
наблюдения в центр. Карточка обновляется с тем же asset_uid; видны источник, свежесть,
статусы секций, ответственная команда и история. Перезапуск не очищает реестр или очередь.

## 3. Capabilities и поля E1

| Область | Входит | Явная граница |
|---|---|---|
| Центральный сервер | Go combined, один PG, миграции, API `/api/v1`, outbox, audit | Нет production multi-instance и физического шардирования |
| Область данных | tenant/site, tenant checks на каждом чтении/записи/job | Пилот одной организации, негативные тесты минимум двух tenant |
| Идентичность | canonical asset_uid, agent_id, collector_id, source-local mapping | Не склеивать молча конфликтующие хосты; полный merge/split — C25 |
| Хост | hostname, доступный machine/BIOS identity candidate, ОС/версия, IP/MAC | Нет обязательного глубокого ПО/KB/CPU/RAM inventory до E2 |
| Наблюдение | observation/source IDs, observed/received time, section status и причина | Недоступный раздел не равен пустому/false/нулю |
| Свежесть | heartbeat, last contact, last successful inventory, completeness | Source health и freshness не являются автоматическим missing/lifecycle |
| Ответственность | обязательная fallback-команда tenant/site при создании | Персональные передачи и оргсинхронизация расширяются в E3 |
| История | сохранение наблюдений и изменений, защита ручных бизнес-полей | Нет удаления карточки вместе с одним scan |
| Collector | постоянная служба; приём агента и доставка в центр | Широкий SSH/WinRM/SNMP discovery — E2 |
| Agent | минимальная служба своего хоста, расписание, heartbeat, защищённая доставка | Не remote shell, deploy/RMM/EDR и не сетевой сканер |
| Доставка | durable spool на agent и collector, receipt/applied, retry/dedup | Intermediate receipt не заменяет подтверждение PG commit |
| Web | отдельные assets, login, список, карточка и диагностика источников | Только API; все права проверяет backend |
| CLI | login/context, assets list/get, sources/status, JSON/exit codes | Использует API; прямой доступ в PG запрещён |
| Секреты | OpenBao для server secret refs/ключевых операций; identities scoped | Полный vault не раздаётся агентам, remote target passwords пока не нужны |
| Эксплуатация | конфиги, service lifecycle, версии, метрики, backup/restore и обновление | SLA/100% uptime не обещаются без измерений |

## 4. Стенд и параметры по умолчанию

Серверный dev-стенд: Linux/amd64, Debian 13; Go/PG/Bao по [решениям](C01-decisions.md).
Первая ОС host agent — **proposed**, решение до C08: Linux/amd64 упрощает текущую проверку;
Windows-first не отклонён пользователем. Его вопрос уточнил серверный приоритет, но не выбрал ОС.
Это не блокирует серверные C02–C07. C01 завершает фиксацию вариантов, а не подтверждает поддержку ОС.

Рабочие defaults для контрактов и будущего стенда (не измеренные показатели):

- Heartbeat 60 секунд, полный E1 inventory 15 минут, jitter ±10%; на тестах интервалы сокращаются явно.
- Источник `stale` после трёх пропущенных heartbeat; инвентарь `stale` после двух своих интервалов.
  Это не означает `asset missing`: полноценная evidence/presence-модель появляется в E2.
- Квота spool 256 MiB на процесс как начальный configurable default. Неподтверждённые записи
  автоматически не удаляются; при заполнении — явный статус, backpressure и ограничение сбора.
- Интервалы, квоты, retention и resource budget корректируются по C10/C14 измерениям;
  срок хранения не должен молча удалять записи, ожидающие центрального ACK.
- E1 тестовый профиль: один реальный agent host, один collector, один central instance;
  отдельные process/data directories даже при общей машине. Две tenant для негативных тестов.
  Отдельные VM/реальная ОС обязательны там, где проверяется reboot/system service.

## 5. Отложено с сохранением целевой архитектуры

E2: Windows/Linux coverage, SSH/WinRM/SNMP, multi-source discovery, evidence-based topology,
portable разового аудита и полный signed/encrypted offline-пакет.
E3: зрелый AM/CMDB, сложная идентификация и full-text Tantivy/Bluge, workload 100 active.
E4: внешние интеграции и миграция данных v1. E5: реплики, SQL pool по нагрузке,
физические шарды, geo DR, multi-process production; модули/outbox/tenant routing abstraction — с начала.
Волна 2: ЖЦ/склад/запчасти/движения; волна 3: ITSM.

## 6. Условия выхода

Каждый включённый capability имеет сценарий в [приёмке](C01-acceptance.md).
C01 не запускает C04 и не объявляет Go-систему реализованной. C08 — ранний живой цикл;
C14 — отдельная эксплуатационная приёмка. Первый следующий пакет — C02.
