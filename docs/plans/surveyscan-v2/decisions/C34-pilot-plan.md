# C34.01 — план пилота (черновик для согласования)

Статус: **решение пользователя 2026-11-12 — пилот на стенде awm.local** (R-027). Остальные поля — по ходу пилота. Поля «решение пользователя» заполняются после ответов; до этого пилот не
начинается. Активные проверки (опрос по SSH/WinRM/SNMP, обнаружение) — только в утверждённых диапазонах.

## 1. Цели пилота (предложение)
1. Реестр отражает все рабочие машины пилотной площадки: ≥ 95 % машин с агентом или удалённым сбором имеют
   свежие данные (≤ 24 ч) в течение всего пилота.
2. У каждого актива есть ответственный (не резервная команда) к концу пилота — ≥ 90 %.
3. Операторы выполняют типовые задачи без разработчика (раздел 5) — все задачи чек-листа.
4. Ни одной потери данных: копия → восстановление на отдельной машине проходит (C33.04).
5. Производительность — по SLO D-18 (уже подтверждено на стенде для 2 000 активов / 100 пользователей).

## 4. Доступы и данные
Учётки: администратор и операторы — локальные SurveyScan (вход через AD — отдельная задача, не в пилоте).
Служебная учётка AD — только чтение (уже есть). Для удалённого сбора — отдельные учётки с минимальными правами
(хранятся в OpenBao, не в документах). Данные пилота остаются на площадке; в репозиторий не попадают.

## 5. Обучение (C34.02) — чек-лист «оператор справляется сам»
По [руководству пользователя](../../../../v2/deploy/USER-GUIDE.md): найти актив; открыть карточку и понять
свежесть; назначить ответственного и передать; разобрать конфликт; выгрузить реестр в Excel и загрузить правки;
найти, где установлено ПО; посмотреть схему сети. Администратор дополнительно: добавить источник (агент, WinRM,
portable), включить AD и уведомления, сделать копию по OPERATIONS.md.

## 6. Откат
Пилот ничего не меняет в инфраструктуре, кроме установленных агентов: откат — удаление агентов (служба и каталог
состояния) и остановка центра. Данные SurveyScan — копия перед началом и после окончания.

## 7. Стабилизация (C34.03) и передача (C34.04)
Реестр замечаний — [pilot/ISSUES.md](../pilot/ISSUES.md) (номер, кто нашёл, суть, приоритет, статус); еженедельный
отчёт — `v2/scripts/pilot_report.py` (только чтение API): свежесть, ответственные, конфликты, источники, AD, уведомления, предупреждения. Передача: отчёт пилота, руководства, владельцы, предложение
SLA/SLO; незакрытые риски перечисляются явно.
